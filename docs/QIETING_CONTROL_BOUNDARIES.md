# 播放控制边界诊断（D002）

`a57693c` / CI #13 的媒体时间线已通过完整 972 项测试及用户真实 Mac 的 13 项使用验收。本报告独立调查暂停、恢复和直接换歌时的短促 Click/Pop，不替换该时钟方案。

## 实际生产输出测量

来源：[CI #17](https://github.com/hoviksinn/kumone/actions/runs/39167132633)，[QieTing-Validation-Evidence-17-1](https://github.com/hoviksinn/kumone/actions/runs/39167132633/artifacts/12151192883) 内的 `playback-boundary-diagnostic.json`。该运行编译通过，音频边界诊断套件的 **6 个用例全部通过并保存结果**；随后 UI 测试失败，因此**不是完整回归通过，也没有新 App 测试包**。此前 CI #16 保存 5 个结果，本次补齐了 96kHz 直接替换用例。输入为程序生成的原创双声道 PCM，经生产 Deck DSP、Limiter 与最终输出离线渲染。96kHz 输入经过现有转换路径，测量输出为 44.1kHz；不是实体 DAC 或听感测量。

| 输入采样率 / 峰值 | 稳态最大相邻样本差 | 暂停边界 | 恢复边界 |
| --- | ---: | ---: | ---: |
| 44.1kHz / 0.08 | 0.002408 | 0.069767 | 0.068557 |
| 44.1kHz / 0.55 | 0.016557 | 0.479648 | 0.471329 |
| 96kHz / 0.08 | 0.002409 | 0.069765 | 0.068554 |
| 96kHz / 0.55 | 0.016560 | 0.479634 | 0.471312 |

中振幅边界突变约为同段正常样本差的 29 倍。四组暂停/恢复都在非零波形与全声道数字静音之间出现突变；没有 NaN、无限值或超出原峰值的冲激。每组 65,536 个有声源帧均按顺序匹配不中断参考输出，最大 PCM 误差为 0；暂停和恢复的媒体位置均为 0.8126984127 秒、同一 generation。恢复填充为 3072 帧，在该实验测得的 5120 帧上限内。

这确认了合成 PCM 的控制边界不连续，同时没有发现本实验中的媒体跳漏或重复；不能据此认定真实 Mac 偶发爆音只有这一个原因。

直接替换歌曲的两个用例均已完成：

| 输入采样率 | 稳态最大相邻样本差 | 替换边界 | 相对稳态 |
| --- | ---: | ---: | ---: |
| 44.1kHz | 0.016557 | 0.094508 | 5.71 倍 |
| 96kHz | 0.016560 | 0.159833 | 9.65 倍 |

两个替换用例都没有全声道数字静音边界，没有非有限样本；替换前后 generation 从 2 变为 5，符合新歌曲重新调度。它们证明直接替换路径也存在显著波形突变，但不能单凭最大差认定是源节点、DSP 重置或增益哪一层造成，更不能把暂停的静音边界检测直接当作换歌修复。

暂停边界出现在指令后仍继续渲染的 DSP 尾部末端，不能在调用 pause 前写一个 ramp 就假定已经执行。包络必须作用于实际送往输出的样本，并有独立渲染证据。

## 早期 3ms 隔离实验（历史证据）

约 3ms lookahead + 极短包络的独立数学实验，对本次实际渲染后保存的合成 PCM 片段再次离线处理，可把暂停/恢复的最大相邻差降到约 0.01656（中振幅）并保留片段内每个帧标识；按 44.1kHz 输出计算，候选固定延迟为 135 帧、约 3.061ms。对 44.1kHz 和 96kHz 直接替换的非静音边界均没有改善。片段裁剪首尾本身也会引入边界，所以它只用于已知中间控制边界的隔离可行性研究。

当时的 3ms 数学原型没有进入 App，既不是实际音频引擎修复前后对照，也不是用户设备验收。后续源码集成状态见下一节；不能把这份早期实验当作最新 App 已消除爆破音的证据。

以下生产集成仍需受支持的实际输出节点、不同设备输出率与 FIFO 生命周期验证，以及 AutoMix/segment、设备切换和严格原始 PCM/处理后 PCM 两层回归。直接换歌的非静音边界仍需独立处理。不能修改 tap 副本就声称真实输出已处理，不能降低原 1e-5 连续性标准、跳秒、Seek 或拉长淡入淡出来隐藏问题。D002 继续开放。

## 生产源码接线：等待原生验收

本提交将候选接入真实的串联输出源码：`mainMixerNode → limiter → masterMixer（用户音量）→ ControlBoundaryEffect → outputNode`。它使用公开的进程内 `AUAudioUnit.registerSubclass` / `AVAudioUnitEffect`，没有扩展、插件安装、新签名、用户数据或应用身份变化；分析 Tap 位于处理器之后，只负责观察。若创建或接线失败，保留可诊断的旧输出回退；原生回归必须断言处理器真实存在、已分配资源且处于唯一串联路径，不能用回退通过验收。

**当前仅完成源码集成、静态核对及便携实验，尚未完成本提交的 macOS SDK 编译、真实 AU 渲染或 App 构建。D002 未验收通过，不能声称用户听到的 Click/Pop 已消失。** 本提交在独立可回退的音频分支准备；PR 的 UI 专项通过后才能接入并触发原生音频专项，再切换 `complete` 做全部回归和安全打包。

最终输出处理器采用预分配 Float32 planar FIFO、所有声道共用的极短包络，按实际协商的最终输出采样率计算。已选候选为 2ms 包络加两帧边界确认：44.1 / 48 / 96kHz 分别为 91 / 98 / 194 帧固定 FIFO 延迟（约 2.063 / 2.042 / 2.021ms）。这些是源码/便携实验中的延迟；宿主对声明 AU latency 的补偿及真实设备额外延迟，必须由原生 impulse 与最终输出测量区分，不能把声明值当成设备测量。

接受暂停时，在现有源节点暂停之前发布边界代次，FIFO 允许在源已暂停之后平滑仍在输出的尾部。恢复时发布有限帧预算；现有 native-ready 重试真正启动源节点前再次发布，不修改其 source render anchor、`play(at:)` 参数或现有重试节奏。等待自然信号有有限预算，避免在长时间编码静音结束后误改下一音符。暂停本身不以墙上经过时间推进源位置；没有额外 Seek、重播、跳帧、音量下降或长淡入淡出。八个原媒体时钟/暂停/恢复辅助函数保持字节相同。

`1e-12`（约 −240dBFS）只用于识别控制代次内全声道的极低电平静音，不将原始样本清零或丢弃。原始 FIFO 和处理后的最终 PCM 分层验证：前者按序对照不中断参考，原 `1e-5` 样本误差和两源帧时钟阈值保留；后者使用独立的数学包络预期，检查有界修改、无放大、无非有限样本以及边界之外不变。测试专用 raw 存储与真实处理器共用 FIFO/实际输出时间戳，默认关闭，只允许离线同步 pull 之间或已静止渲染时读取；不能将此读接口用于与实时渲染并发取样。单独 live segment 测试使用现有最终输出 Tap 的预分配缓冲，避免并发读取 AU raw ring。

普通暂停、恢复、Deck 退役及 segment 交接不 reset 最终 FIFO。公开 AU reset 和资源重新分配仍正确失效旧时间戳及捕获 epoch；新增断言检查普通操作中这些计数不变。渲染块内不分配、不加锁、不触发 Swift/Objective-C 回调、不记录日志；用户控制仍由原有串行引擎队列排序。

### 已执行的便携证据及限制

- 129 组内核实验、15 组有限等待边界、61 组从实际 C++ `RenderState` 提取的状态实验、348 组保存的旧合成波形回放已通过。15 组实验先复现无限等待误改自然下一音符的问题，再验证有限预算修正。它们不包含 Apple SDK、AU 注册或 AVAudioEngine。
- 2ms 方案回放旧 CI 合成片段时，中振幅暂停相邻差约 `0.47965 → 0.01656`，恢复约 `0.47133 → 0.01656`，原始帧顺序误差 0。这些不是本提交通过生产引擎新渲染的修复前后数据，更不是实体 DAC/耳机测量。
- 内核地址/未定义行为 sanitizer 通过；当前 Linux ptrace 环境不支持 LeakSanitizer，不声称泄漏检查通过。
- 从真实 `RenderState` 提取的 Linux 性能实验覆盖 24 配置、99,648 次准备后的首次/warmup/正式 callbacks，经自检的堆分配 hooks 为 0。共享 KVM 存在毫秒级调度长尾，不能据此保证 Mac 硬实时、功耗或设备延迟。

### 新增原生门槛与仍未覆盖的输出边界

新增 11 个 `ControlBoundaryOutputTests` 声明与 1 个 live segment 声明：实际注册桥接、双边界、真实 impulse/EOF 尾部、3×3 输入/输出采样率、0.1/1/5/10 秒渲染暂停、30 轮控制、无 IO 快速指令、自然长静音、双 Deck、缺失时间戳、显式 reset/换率重建、延迟 native-ready 和实际 segment 最终输出。原 2 个边界诊断与全部时钟/PCM 测试保留；针对输出的组合至少 14 个声明，完整 Swift Testing 最低计数为 `999 + 12 = 1011`，不重复计算前置专项或参数组合。上述新增用例尚未在 Mac 执行，静态语法成功不能替代原生结果。

实际设备的预取深度不能仅由 `maximumFramesToRender` 推断。有限预算目前记录 AU processing latency、输出/声明 quantum 与可测的同采样率离线 lead 来源；原生延迟启动及设备行为仍必须验证。AirPlay 等设备呈现延迟不拿来补媒体时钟。

本检测器只覆盖明确控制代次内、至少两帧的全声道近静音边界。非零到非零直接换歌、没有近静音边界的 wet-delay 尾部、过短间隙及首次自然起音不作普遍修复承诺。连续输出混合/交接应保持原始信号；不能为凑齐“已修复”而给全部曲目常态添加包络。需要先取得真实生产输出的暂停与恢复测量，再由用户在 Hi-Res/无损中等振幅片段、快速控制、耳机/扬声器、多设备及 AutoMix 场景复测。
